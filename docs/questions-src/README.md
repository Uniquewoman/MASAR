# خط إنتاج الأسئلة

يكتب الأسئلة في ملف بيانات، يفحصها آلياً بعقد الجودة، ثم يولّد SQL جاهزاً.
وُضِع هنا لأن صلاحية الكتابة على قاعدة البيانات كانت معطّلة، ولأن الفحص
قبل الإدخال أرخص بكثير من إصلاح ٩٠ سؤالاً بعده.

## الاستخدام

```bash
node docs/questions-src/check.mjs   docs/questions-src/<batch>.mjs
node docs/questions-src/gen-sql.mjs docs/questions-src/<batch>.mjs docs/sql/questions/<batch>.sql "العنوان"
```

`check.mjs` يجلب عناوين المسار الحيّة من Supabase بالمفتاح العام (قراءة فقط)
فيبقى فحص التكرار صحيحاً كلما نما البنك. لا يُدخِل شيئاً ولا يعدّل شيئاً.

## ما يفحصه

| الفحص | المعيار |
|---|---|
| العدد وتوزيع الأنواع | ٩٠ = ٣٠ اختيار + ١٠ لكل نوع من الستة |
| توزيع الصعوبة | صف المستوى في جدول التدرّج بـ`docs/CURRICULUM.md` |
| مواضع الإجابة | كل موضع بين ٦ و٩ من ٣٠ (~٢٥٪) |
| فجوة الطول | الصحيحة لا تزيد عن أطول بديل بـ٧ أحرف |
| الصحيحة شاذة | كلمة في كل البدائل وليست في الصحيحة |
| تسرّب المصطلح | كلمة من السؤال حصرية بالصحيحة |
| التكرار | داخل الدفعة وعبر المسار كله |
| البنية | شرح لكل سؤال · ٤ خيارات · ≥٣ أزواج توصيل · ≥٤ خطوات ترتيب · مقطع لكل كود · إجابات ووسم لكل تيرمنال |

الفحصان الدلاليان يعطيان إنذارات كاذبة أحياناً (سؤال «ما الفرق بين س وص»
طبيعي أن تحوي إجابته الكلمتين)، فهما مساعدان لا بديل عن القراءة اليدوية.
وما لا يفحصه أي آلة: **صحة السؤال وصحة إجابته** — تُتتبَّع أسئلة الكود
سطراً سطراً يدوياً قبل الاعتماد.

## تدوير المواضع

ملف الدفعة يكتب الإجابة الصحيحة حيث شاء الكاتب، ثم يدوّرها آلياً في نهايته
على المواضع الأربعة (٨/٨/٧/٧ للاختيار و٣/٣/٢/٢ للكود). الخلط العشوائي
منحاز على عيّنة بهذا الحجم، ولذلك التدوير صريح لا عشوائي.

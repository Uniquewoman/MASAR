# خطة المحتوى التعليمي — مسار

المرجع المعتمد لتوزيع المواضيع على المستويات. **أي سؤال يُضاف للداتابيس لازم يتبع هذي الخطة.**

## القواعد

| القاعدة | القيمة |
|---|---|
| مستويات كل قسم | ٥ |
| بنك الأسئلة لكل مستوى | **٩٠** سؤال (هدف مرحلي، يُرفع لاحقاً) |
| يُسحب في المحاولة | ٣٦ = ٣٠ صحيحة + ٦ أخطاء |
| العبور | ٣٠ إجابة **صحيحة** |
| الفشل | ٦ أخطاء |
| عدم التكرار | لا يتكرر سؤال حتى تنتهي أسئلة المستوى، ثم تبدأ دورة جديدة مخلوطة |

### مبدأ ترتيب المواضيع
- كل مستوى ياخذ **٢–٣ مواضيع مترابطة**
- **ما يتكرر موضوع** بين مستويين — كل موضوع له مكان واحد
- **ما ينحط موضوع قبل متطلبه**
- L5 دائماً أصعب مواضيع القسم

### توزيع أنواع الأسئلة — ثابت لكل مستوى

من أصل ٩٠ سؤال في كل مستوى:

| النوع | العدد |
|---|---|
| اختيار من متعدد | **٣٠** |
| كود | ١٠ |
| صح وخطأ | ١٠ |
| ماتش | ١٠ |
| تيرمنال | ١٠ |
| اختيار متعدد الإجابات | ١٠ |
| ترتيب الخطوات | ١٠ |

الذي يتغيّر بين المستويات هو **المواضيع والصعوبة**، لا عدد كل نوع.

### تدرّج الصعوبة داخل المستوى

| المستوى | `easy` | `medium` | `hard` |
|---|---|---|---|
| L1 | ٥٠٪ | ٤٠٪ | ١٠٪ |
| L2 | ٣٥٪ | ٤٥٪ | ٢٠٪ |
| L3 | ٢٥٪ | ٥٠٪ | ٢٥٪ |
| L4 | ١٥٪ | ٥٠٪ | ٣٥٪ |
| L5 | ١٠٪ | ٤٥٪ | **٤٥٪** |

> ملاحظة تقنية: الأسئلة تُخلط عشوائياً بالكامل عند كل محاولة (Fisher‑Yates)، ثم تُوزَّع بحيث لا يتجمّع نفس الموضوع أو النوع في أسئلة متتالية. لا تعتمدي على `question_order` لترتيب العرض — هو للأرشفة فقط.

### نموذج مكتمل يُحتذى: البرمجة / أساسيات / L1

٩٠ سؤالاً نشطاً فريداً بلا تكرار، موضوعان فقط (التعليقات والمتغيرات)،
بالتوزيع المعتمد: ٣٠ اختياري + ١٠ لكل نوع من الستة الباقية.

> **عن الأسئلة المعطّلة:** الأسئلة الزائدة عن التوزيع لم تُحذف بل عُطّلت بـ`is_active = false`
> وتبقى في الداتابيس. الاستعلام يستثنيها، ويمكن إعادة تفعيل أي منها بتغيير الحقل.
> عند الاختيار تُعطى الأولوية للأسئلة **الأصعب** لأنها الأكثر قيمة.

### فحص التكرار — إلزامي قبل اعتماد أي مستوى

```sql
select level, count(*) filter (where is_active) as نشط,
       count(distinct question) filter (where is_active) as فريد
from public.questions
where track_id = '...' and section_id = '...'
group by level order by level;
```

لا بد أن يتساوى العمودان. عند وجود نسخ مكرّرة تُعطَّل النسخة الأحدث (`id` الأكبر) ويبقى الأصل.
وُجد ١٧ سؤالاً مكرّراً حرفياً في مستوى ٢ من البيانات الأصلية وعُولجت بهذه الطريقة.

### معايير جودة السؤال
- واقعي من ممارسة فعلية، مو حفظ نظري
- **الخيارات الخاطئة معقولة** — أخطاء يقع فيها المبتدئ فعلاً، لا حشو واضح
- ملتزم بموضوع مستواه، ما يخرج عنه
- غير مكرر مع أي سؤال موجود

### ⚠️ ألّا تكشف الإجابة الصحيحة نفسها

ثلاثة تلميحات تجعل اليوزر يخمّن بلا فهم، وكلها ممنوعة:

**١. الطول** — لا تكون الإجابة الصحيحة أطول من كل البدائل. الشرح مكانه حقل
`explanation` لا داخل الخيار. اجعلي أطوال الخيارات متقاربة.

> ⚠️ **درس متكرر:** كتابة "بدائل متقاربة الطول" وقت الإدخال بالعين وحدها **لا تكفي** —
> حدث ثلاث مرات أن دفعة "منتبهة للطول" رجعت بنسبة ٥٠–٦٠٪ رغم النية. لازم تشغيل
> استعلام فحص الطول (أدناه) **فوراً بعد كل دفعة إدخال، قبل الدفعة التالية**، لا في
> نهاية المستوى — تصحيح ٩٠ سؤال دفعة واحدة أبطأ بكثير من تصحيح ٣٠.

**٢. المجال الدلالي** — البدائل يجب أن تكون في نفس مجال الإجابة الصحيحة وتبدو
معقولة. خيار مثل "لتقليل حجم الملف" أمام إجابة عن المنطق يُستبعد فوراً بلا تفكير.
اجعلي كل بديل خطأً شائعاً حقيقياً أو التباساً واردًا.

**٣. الموضع** — لا تتركّز الإجابة الصحيحة في موضع معيّن. كان التوزيع ٥١٪ في
الموضع الأول و٠.٦٪ في الأخير، أي أن اختيار الأول دائماً يعطي ٥١٪ بلا قراءة.

فحص الموضع:
```sql
select correct_answer, count(*),
       round(100.0*count(*)/sum(count(*)) over (),1) as نسبة
from public.questions
where type='multiple-choice' and is_active and jsonb_array_length(options)=4
group by correct_answer order by correct_answer;
```
المطلوب: كل موضع بين ٢٠٪ و٣٠٪ تقريباً.

لتوزيع المواضع بالتساوي على مستوى جديد، ضعي الإجابة الصحيحة في موضع يتناوب
`0,1,2,3` بدل الاعتماد على خلط عشوائي (العشوائي على عيّنة صغيرة يعطي ميلاً واضحاً):

```sql
with target as (
  select id, options, correct_answer,
         (row_number() over (order by md5(id::text || 'seed')) - 1) % 4 as want
  from public.questions
  where section_id = '...' and level = N
    and type in ('multiple-choice','code') and jsonb_array_length(options) = 4
),
parts as (
  select t.id, t.want, (t.options ->> t.correct_answer) as correct_txt,
         (select jsonb_agg(v order by ord)
            from jsonb_array_elements_text(t.options) with ordinality x(v, ord)
           where ord - 1 <> t.correct_answer) as others
  from target t
),
built as (
  select id, want,
    coalesce((select jsonb_agg(v) from (select value v from jsonb_array_elements(others) limit want) s), '[]'::jsonb)
    || jsonb_build_array(to_jsonb(correct_txt))
    || coalesce((select jsonb_agg(v) from (select value v from jsonb_array_elements(others) offset want) s2), '[]'::jsonb)
    as new_options
  from parts
)
update public.questions q set options = b.new_options, correct_answer = b.want
from built b where q.id = b.id;
```

فحص الطول:
```sql
with opt as (
  select q.id, length(t.value) as len, (t.ord-1)=q.correct_answer as ok
  from public.questions q,
       lateral jsonb_array_elements_text(q.options) with ordinality t(value, ord)
  where q.type='multiple-choice' and q.is_active
)
select round(100.0*count(*) filter (where lc > lo)/count(*),1) as نسبة_الصحيحة_الأطول
from (select id, max(len) filter (where ok) lc, max(len) filter (where not ok) lo
      from opt group by id) a;
```
المطلوب: قريبة من ٢٥٪، لا ٥٠٪.

## الذكاء الاصطناعي

> **الخطة أُعيد تصميمها في ٢٦ أغسطس ٢٠٢٦** بعد مراجعة تسلسل المواضيع، بحيث تكون مواضيع
> أساسيات الذكاء الاصطناعي متدرّجة من الأساسيات بلا قفز، ونفس الشي لباقي أقسام
> المسار بحيث يخرج المتعلّم فاهماً بلا تشتّت. مفاتيح الأقسام السبعة لم تتغيّر (مثبّتة بالكود)،
> المتغيّر توزيع المواضيع على المستويات. أسباب الانحراف عن الخطة الأولى موثّقة تحت الجدول.

| القسم | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| S1 أساسيات | ما هو الذكاء الاصطناعي · تاريخه | كيف يعمل النظام: بيانات ← تدريب ← نموذج ← استدلال · الميزة والوسم | أنواع التعلّم الثلاثة: مُشرف · غير مُشرف · معزّز | خريطة المجال: AI وML وDL · فكرة الشبكة العصبية · مجالات التطبيق | حدود الأنظمة وأخطاؤها · الأخلاقيات والتحيّز والخصوصية |

### لماذا انحرفت هذي الخطة عن الأولى — أربعة أسباب موثّقة

| التغيير | الخطة الأولى | السبب |
|---|---|---|
| **بايثون انتقل من S1 L3 إلى S2 L1** | كان في وسط القسم الأول | كان يقطع الخيط المفاهيمي (بين "الأنواع" و"الفرق بين AI/ML/DL")، ويُدرَّس قبل استخدامه بقسم كامل. مكانه الآن أول قسم يحتاجه فعلاً، فيصير S1 مفاهيمياً خالصاً بلا متطلب برمجي |
| **أُضيف "كيف يعمل النظام" في S1 L2** | لم يكن موجوداً أصلاً | دورة (بيانات ← تدريب ← نموذج ← استدلال) هي النموذج الذهني الأهم بالمجال كله، وكانت غائبة من الخطة رغم أن كل قسم لاحق يفترضها مفهومة |
| **دُمج "الأنواع" و"الفرق بين AI/ML/DL" في S1 L4** | كانا في L2 وL4 منفصلين | كلاهما تصنيف للمجال، ففصلهما بمستويين أنتج تداخلاً وتكراراً |
| **التعلّم المعزّز قبل الروبوتات في S7** | الروبوتات L1 والمعزّز L2 | الروبوت يتعلّم بالتعلّم المعزّز، فتدريسه أولاً قلب الترتيب |

### التضمين Embeddings — قرار موضعي

يُدرَّس في **S4 L5** مع المحوّلات لأنه مدخلها الفعلي، لا في S5 L1.
لذلك S5 L1 يغطي **التمثيل النصي التقليدي** (BoW وTF-IDF) فقط، وS5 L5 (RAG) يبني على تضمين دُرِّس سلفاً.

**أهم ما كشفه التدقيق — اختلاط موضوع لا تكرار عنوان:** كان اسم الموضوع
`Protocol Choice` مستعملاً في L2 وL5 معاً، وتبيّن أن ثمانية من أسئلة L5
تعيد صياغة ما درّسه L2 عن اختيار TCP مقابل UDP: متى يُختار الموثوق، ومتى
عديم الاتصال، وترتيب خطوات الاختيار، وتوصيل كل حاجة بناقلها. كلها بصياغة
مختلفة ومضمون واحد.

**العلاج لم يكن إعادة تسمية الموضوع.** أُعيدت كتابة الأسئلة الثمانية بمضمون
يخص الطبقة العليا وحدها (منافذ البروتوكولات · بدائلها المشفَّرة · اعتماد
بروتوكول جديد)، وبقي في L5 من أمر النقل ما يخصّه فعلاً: **لماذا اختار
بروتوكولٌ بعينه ناقلاً بعينه** — كترجمة الأسماء فوق عديم الاتصال ونقل
الملفات فوق الموثوق. ثم أُعيد اسم الموضوع `Protocol Selection` تمييزاً.

**القاعدة المستخلَصة:** تطابق اسم الموضوع بين مستويين إنذار لا مجرد تنسيق —
يُقرأ محتوى المستويين قبل تغيير الاسم، فإن تطابق المضمون فالعلاج إعادة كتابة
لا إعادة تسمية.

**أهم ما كشفه التدقيق:** حالتان من الخمس لم تكونا تصادم عناوين بل **تكرار
محتوى فعلي** مع L1 — سؤال ترتيب بخطواته الأربع نفسها، وسيناريو ربط مبنيين
تحسمه الألياف. إعادة التسمية كانت ستُخفي التكرار لا تُزيله، فاستُبدِل
السؤالان بمحتوى مختلف. **القاعدة المستخلَصة: قبل إعادة تسمية أي عنوان
متكرر، يُقرأ محتوى السؤالين — فإن تطابق المحتوى فالعلاج استبدال لا تسمية.**

**وحدّ مقصود في التخطيط:** القناع في L4 مفهوم لا حساب، وتقسيم الشبكات
الفرعية بحسابه الكامل تُرك لموضعه في S2 L3. وكذلك المنافذ في L5: ذُكرت
بقدر ما يُفهَم به كيف يعرف الخادم أي خدمة تُقصَد، وتفصيلها في S2.

**الأهم في هذا التدقيق:** فحص التسرّب على **المسار كله** كشف ٢٨ حالة لم تظهر في
تدقيقات الأقسام السابقة — أكثرها في المستويين الأول والثاني من كل قسم، أي ما كُتِب
قبل أن يدخل الفحص خط الإنتاج. النمط واحد: كلمة من نص السؤال ترد في الإجابة الصحيحة
وحدها («الثغرات» · «الجلسة» · «الصلاحيات» · «المفتاح» · «التخزين» …) فيلتقطها المتعلّم
بالشكل بلا فهم. العلاج كان بتوحيد المحور اللفظي بين الخيارات الأربعة، لا بحذف سؤال واحد.

**ودرس ثانٍ:** ست حالات جديدة ظهرت **بعد** دفعة الإصلاح نفسها — لأن إعادة صياغة بديل
تنقل الشذوذ من طرف لآخر. فلا يُعتمد إصلاح تسرّب إلا بإعادة تشغيل الفحوصات الثلاثة بعده.

| ٦ | شمول المواضيع | القسم يغطي ما يحتاجه أمن الشبكات. **ملاحظة للقسم الثالث:** الخدمات المستمعة والسجلات والوصول الآمن عن بُعد مغطّاة هنا، ويبدأ قسم أمن الأنظمة من صلاحيات النظام نفسه بلا افتراض سابق |

**إصلاحات بنيوية أثناء التدقيق:** ثلاثة أسئلة `matching` كان الطرف الأيمن فيها متكرراً (TCP/UDP مرتين، صحيح/غير صحيح مرتين) فتعذّر التوصيل واحداً لواحد — أُعيدت صياغة أطرافها لتصير كل قيمة فريدة (اثنان في هذا القسم وواحد في قسم الأساسيات id 6830).

### 🧾 تدقيق اكتمال قسم «التوجيه والتبديل» (`Routing and Switching`) — ٧ سبتمبر ٢٠٢٦

٤٥٠ سؤالاً في خمسة مستويات: التبديل وجدول العناوين · الشبكات الافتراضية · أساسيات
التوجيه · الثابت والديناميكي · البروتوكولات الثلاثة.

| الخطوة | النتيجة |
|---|---|
| ١ قراءة ١٠٠ سؤال عشوائي من كل المستويات والأنواع | كل إجابة تطابق شرحها ومستواها |
| ٢ تتبّع الأسئلة الحسابية | لا حساب في هذا القسم عدا مجاميع كلف OSPF ومسافات EIGRP، تُتبِّعت يدوياً |
| ٣ عدم اختلاط المواضيع | صفر `topic` خارج مستواه · أُصلح استعمال «حالة الوصلة» في L3 قبل تدريسه في L4 |
| ٤ فحوصات الكشف الثلاثة على القسم كله | صفر بعد إصلاح ٤ حالات تسرّب في L1 وL2 |
| ٥ فحص التسلسل | أحد عشر مصطلحاً فُحص أول ظهوره مقابل مستوى تدريسه — إنذار واحد حقيقي أُصلح |
| ٦ شمول المواضيع | القسم يغطي مجاله: قرار المبدّل، العزل المنطقي، حسم المسار، مصادر المسار، البروتوكولات |

**عيب من صنف جديد كشفته الخطوة الأولى:** شروح تشير إلى **مواضع** الخيارات
(«الأخيران…») بينما تدوير مواضع الإجابة الصحيحة نقلها. مرّت الفحوصات الآلية كلها
لأن الإجابة صحيحة والشرح صحيح، والخلل في **الإحالة** بينهما. فُحص البنك كله:
١١ حالة في الشبكات · ٦ في البرمجة والأمن السيبراني · ٤٩ في التقنية المالية —
عولجت كلها بتسمية الخيارين بدل الإشارة لموضعهما.

**قاعدة مضافة:** لا يُكتب في الشرح «الأول/الأخير/الثاني»، بل يُسمّى الخيار نصاً —
فالمواضع تتغيّر بالتدوير والشرح لا يتغيّر معها.

### 🧾 تدقيق اكتمال قسم «خدمات الشبكات» (`Network Services`) — ٧ سبتمبر ٢٠٢٦

٤٥٠ سؤالاً: الأسماء · توزيع العناوين · الترجمة · الأنفاق · المراقبة والتكامل.

| الخطوة | النتيجة |
|---|---|
| ١ قراءة ٩٥ سؤالاً عشوائياً من كل المستويات والأنواع | كل إجابة تطابق شرحها ومستواها |
| ٢ تتبّع الأسئلة الحسابية | لا حساب رقمياً في القسم عدا نسب الاستهلاك وقراءات القياس، تُتبِّعت |
| ٣ عدم اختلاط المواضيع | صفر `topic` خارج مستواه |
| ٤ فحوصات الكشف الثلاثة | صفر بعد إصلاح ٨ حالات تسرّب في L1 وL2 وفجوة طول واحدة |
| ٥ فحص التسلسل | ثمانية مصطلحات فُحصت — إنذار «الترجمة» في L1 كاذب: المقصود ترجمة **الأسماء** لا العناوين |
| ٦ شمول المواضيع | القسم يغطي مجاله، والمستوى الخامس يربط الأربعة السابقة بخريطة اعتماد |

**تكرار محتوى خلف عنوانين مختلفين:** «ما خطر ضبط عنوان ثابت داخل نطاق التوزيع؟»
و«ما الخطر في ضبط عنوان يدوي داخل نطاق التوزيع؟» سؤالان مختلفا العنوان متطابقا
المضمون والخيارات — لم يمسكهما فحص تكرار العناوين لأنه يقارن النص حرفياً. أُعيدت
كتابة الثاني ليسأل عن **علاج** التعارض (استثناء المدى) لا عن خطره.

**قاعدة مضافة:** فحص التكرار الحرفي لا يكشف تكرار المضمون. عند كتابة سؤالين متجاورين
في الموضوع نفسه، تُقرأ خياراتهما معاً — تطابق الخيارات تكرار وإن اختلف العنوان.

### 🧾 تدقيق اكتمال قسم «اللاسلكي والسحابي» (`Wireless and Cloud Networking`) — ٨ سبتمبر ٢٠٢٦

٤٥٠ سؤالاً: أساسيات اللاسلكي · المعايير والأمن · تخطيط التغطية · الشبكات
السحابية · الافتراضية والمعرَّفة برمجياً.

| الخطوة | النتيجة |
|---|---|
| ١ قراءة ٤٢ سؤالاً عشوائياً من كل المستويات والأنواع | كل إجابة تطابق شرحها ومستواها |
| ٢ تتبّع الأسئلة الحسابية | لا حساب رقمياً في القسم؛ القراءات وصفية وتُتبَّع منطقياً |
| ٣ عدم اختلاط المواضيع | صفر `topic` خارج مستواه |
| ٤ فحوصات الكشف الثلاثة | صفر بعد إصلاح ٤ حالات تسرّب في L1 وL2 |
| ٥ فحص التسلسل | تسعة مصطلحات فُحصت — «مسح الموقع» ظهر في L1 قبل تدريسه في L3، فأُبدِل بـ«قياس التغطية في الموقع» |
| ٦ شمول المواضيع | القسم يتدرّج من الموجة إلى التخطيط إلى السحابة إلى المبدأ الذي تقوم عليه |

**تكرار عنوان عام:** «ما الذي يعالج هذا الخطر؟» ظهر في S3 L2 وS5 L5 بمحتويين
مختلفين — أُعيدت تسمية الثاني إلى «ما الذي يعالج هذا الخطر في التصميم المركزي؟».

**ملاحظة على فحص التسرّب:** إصلاح التسرّب قد يخلق تسرّباً معاكساً — أُضيفت كلمة
للبدائل فاختفت منها كلمة أخرى كانت تغطّي الصحيحة. القاعدة: بعد كل إصلاح تُعاد
قراءة **كل** كلمات نص السؤال الواردة في الصحيحة، ويُتحقَّق أن كل واحدة منها
موجودة في بديل واحد على الأقل.

### 🧾 تدقيق اكتمال قسم «أمن الشبكات» (`Network Security`) — ٨ سبتمبر ٢٠٢٦

٤٥٠ سؤالاً: المبادئ والتهديدات · الجدران · الكشف والمنع · القوائم والتقسيم ·
تصميم شبكة آمنة.

| الخطوة | النتيجة |
|---|---|
| ١ قراءة ٤٠ سؤالاً عشوائياً من كل المستويات والأنواع | كل إجابة تطابق شرحها عدا واحدة أُصلحت |
| ٢ تتبّع الأسئلة الحسابية | لا حساب رقمياً في القسم؛ التصنيفات والقراءات تُتبَّع منطقياً |
| ٣ عدم اختلاط المواضيع | صفر `topic` خارج مستواه |
| ٤ فحوصات الكشف الثلاثة | صفر بعد إصلاح ٦ حالات تسرّب وحالة شذوذ واحدة |
| ٥ فحص التسلسل | عشرة مصطلحات فُحصت — التقسيم والمنطقة منزوعة السلاح يظهران في L1 تعريفاً وفي L4 تطبيقاً، وهو تدرّج مقصود لا قفزة |
| ٦ شمول المواضيع | القسم يتدرّج من التهديد إلى الأداة إلى التصميم الذي يجمعها |

**تكرار مضمون بين مستويين:** سؤالان في L4 («الغرض الأمني من التقسيم» و«المنطقة
منزوعة السلاح») كانا يعيدان ما عرّفته L1 بصياغة أخرى. لم يكفِ تغيير العنوان،
فأُعيدت كتابتهما ليسألا عمّا لا تجيبه L1: **أثر التقسيم على تشخيص الأعطال**،
و**ما يُمنَع من المنطقة منزوعة السلاح نحو الداخل**.

**قاعدة مضافة:** حين يتكرر مفهوم بين مستوى تعريفي ومستوى تطبيقي، يُفحَص السؤال
لا الاسم: إن كان يسأل عن **التعريف نفسه** فهو تكرار يُعاد كتابته، وإن كان يسأل
عن **أثره أو حدوده أو ثمنه** فهو تعميق مطلوب.

### 🧾 تدقيق اكتمال قسم «الإدارة والأعطال» (`Network Administration and Troubleshooting`) — ٩ سبتمبر ٢٠٢٦

٤٥٠ سؤالاً: أدوات المراقبة والتوثيق · منهجية الاستكشاف · الطبقات الدنيا ·
الطبقات العليا · تحسين الأداء.

| الخطوة | النتيجة |
|---|---|
| ١ قراءة عيّنة عشوائية من كل مستوى وكل نوع (٣٥ سؤالاً) | كل إجابة تطابق شرحها · كشفت تكراراً مضمونياً بين L2 وL4 (انظر أدناه) |
| ٢ تتبّع الأسئلة الحسابية | لا حساب رقمياً في القسم؛ أسئلة الكود قراءات تشخيصية تُتبَّع منطقياً |
| ٣ عدم اختلاط المواضيع | صفر `topic` خارج مستواه · الطبقتان الأوليان محصورتان في L3 وما فوقهما في L4 |
| ٤ فحوصات الكشف الثلاثة | صفر بعد إصلاح ٨ حالات تسرّب وثلاث حالات شذوذ |
| ٥ فحص التسلسل | ١٤ مصطلحاً فُحص — كشف **تضارب تسمية** (انظر أدناه) |
| ٦ شمول المواضيع | القسم يتدرّج من القياس إلى التشخيص طبقةً طبقة إلى التحسين · **جودة الخدمة** لم تكن مغطّاة في أي قسم سابق فأُدخلت في L5 |

**تكرار مضمون بين مستويين:** سؤالان في L4 («توقف تتبّع المسار عند قفزة» اختياري
وصح/خطأ) كانا يعيدان ما تعلّمه L2 بصياغة أخرى — لم يكشفهما فحص التكرار الحرفي،
بل قراءة العيّنة. أُعيدت كتابتهما إلى **تعدد المسارات وتوزيع الحمل**، وبقي سؤال
الكود لأنه تطبيق على قراءة فعلية لا تعريف.

**تضارب تسمية (سبب جديد يكشفه فحص التسلسل):** التبديل والتوجيه L2 يسمّي الوصلة
الحاملة للشبكات الموسومة **«منفذ النقل»**، بينما كان L3 هنا يسمّيها **«وصلة
الجذع»**. المفهوم واحد والاسمان مختلفان، فيلقى المتعلّم مصطلحاً لم يُدرَّس.
أُوحِّدت ستة أسئلة على «منفذ النقل».

**قاعدة مضافة:** فحص التسلسل لا يكفي فيه أن يكون المفهوم قد دُرِّس، بل أن
يُدرَّس **بالاسم نفسه**. اسم ثانٍ لمفهوم واحد قفزة وإن كان المفهوم مألوفاً.

### 🧾 تدقيق اكتمال مسار الشبكات (`Networking`) — ٩ سبتمبر ٢٠٢٦

٣١٥٠ سؤالاً · ٣٥ مستوى × ٩٠ · التوزيع الثابت مطابق في كل مستوى.

| الفحص | النتيجة |
|---|---|
| العدد والتوزيع | صفر مستوى خارج ٩٠ · صفر مستوى يخالف توزيع الأنواع |
| فجوة الطول ≥٧ | صفر |
| «الصحيحة شاذة» | صفر بعد إصلاح ٣ حالات |
| كلمة سؤال حصرية بالصحيحة | ٥ إنذارات بقيت، كلها إنذارات كاذبة موثّقة (أسئلة مقارنة «ما الفرق بين س وص» وأسئلة تعريف) |
| التكرار الحرفي عبر المسار | صفر |
| الشرح المفقود | صفر |
| عيوب البنية | صفر (ماتش ≥٣ أزواج · ترتيب ≥٤ خطوات · كل كود له مقطع · كل تيرمنال له إجابات) |
| مواضع الإجابة | ٣٧٤ / ٣٦٩ / ٣٢٩ / ٣٢٨ — ٢٦٫٦٪ · ٢٦٫٢٪ · ٢٣٫٤٪ · ٢٣٫٣٪ |

**عيب كشفه التدقيق على مستوى المسار وحده — توازن صح/خطأ:** تسعة مستويات (كلها
L1 وL2 كُتبت قبل أن يفرض `check.mjs` التوازن) كانت ٧ صح مقابل ٣ خطأ أو ٨ مقابل
٢. المتعلّم الذي يجيب «صح» دائماً كان يصيب ٧٠–٨٠٪ من أسئلة صح/خطأ فيها بلا فهم.
أُعيدت صياغة **٢٢ عبارة** لتصير خاطئة (كل واحدة تمثّل سوء فهم حقيقياً: «الإنترنت
شبكة محلية» · «البث يعبر الموجّه» · «العنوان الفيزيائي يتغيّر بالانتقال» …)
فصارت التسعة ٥/٥. باقي المستويات بين ٥/٥ و٦/٤ وهو ضمن النطاق المقبول.

**قاعدة مضافة:** توازن صح/خطأ يُفحَص **على المسار كله عند اكتماله**، لا على
المستوى وحده — لأن الانحراف تراكم في المستويات الأولى قبل أن يُضاف الفحص، فلم
يره أحد حتى قُرِئ المسار مجتمعاً.

### 🧾 تدقيق اكتمال قسم «أساسيات التقنية المالية» (`Fundamentals`) — ٩ سبتمبر ٢٠٢٦

| الخطوة | النتيجة |

**تكرار مضمون بين مستويين:** «ما المقصود بالشمول المالي؟» كُتِب في L5 وهو
معرَّف أصلاً في L1. لم يكفِ تغيير العنوان، فأُعيدت كتابة السؤال ليسأل عمّا لا
تجيبه L1: **ما الذي يضيفه قيد «المناسبة»** — أي أن الوصول وحده لا يكفي.
وأُعيدت كتابة سؤال التيرمنال للسبب نفسه.

**توازن صح/خطأ:** L1 وL2 كانا ٧ صح مقابل ٣ خطأ (كُتِبا قبل فرض الفحص)،
فأُعيدت صياغة أربع عبارات لتصير خاطئة فصار المستويان ٥/٥ — تطبيقاً للقاعدة
المضافة في تدقيق مسار الشبكات.

# خطة المحتوى التعليمي — مسار

المرجع المعتمد لتوزيع المواضيع على المستويات. **أي سؤال يُضاف للداتابيس لازم يتبع هذي الخطة.**

## القواعد

| القاعدة | القيمة |
|---|---|
| مستويات كل قسم | ٥ |
| بنك الأسئلة لكل مستوى | **٩٠** سؤال (هدف مرحلي، يُرفع لاحقاً) |
| يُسحب في المحاولة | ٣٦ = ٣٠ صحيحة + ٦ أخطاء |
| العبور | ٣٠ إجابة **صحيحة** |
| الفشل | ٦ أخطاء |
| عدم التكرار | لا يتكرر سؤال حتى تنتهي أسئلة المستوى، ثم تبدأ دورة جديدة مخلوطة |

### مبدأ ترتيب المواضيع
- كل مستوى ياخذ **٢–٣ مواضيع مترابطة**
- **ما يتكرر موضوع** بين مستويين — كل موضوع له مكان واحد
- **ما ينحط موضوع قبل متطلبه**
- L5 دائماً أصعب مواضيع القسم

### توزيع أنواع الأسئلة — ثابت لكل مستوى

من أصل ٩٠ سؤال في كل مستوى:

| النوع | العدد |
|---|---|
| اختيار من متعدد | **٣٠** |
| كود | ١٠ |
| صح وخطأ | ١٠ |
| ماتش | ١٠ |
| تيرمنال | ١٠ |
| اختيار متعدد الإجابات | ١٠ |
| ترتيب الخطوات | ١٠ |

الذي يتغيّر بين المستويات هو **المواضيع والصعوبة**، لا عدد كل نوع.

### تدرّج الصعوبة داخل المستوى

| المستوى | `easy` | `medium` | `hard` |
|---|---|---|---|
| L1 | ٥٠٪ | ٤٠٪ | ١٠٪ |
| L2 | ٣٥٪ | ٤٥٪ | ٢٠٪ |
| L3 | ٢٥٪ | ٥٠٪ | ٢٥٪ |
| L4 | ١٥٪ | ٥٠٪ | ٣٥٪ |
| L5 | ١٠٪ | ٤٥٪ | **٤٥٪** |

> ملاحظة تقنية: الأسئلة تُخلط عشوائياً بالكامل عند كل محاولة (Fisher‑Yates)، ثم تُوزَّع بحيث لا يتجمّع نفس الموضوع أو النوع في أسئلة متتالية. لا تعتمدي على `question_order` لترتيب العرض — هو للأرشفة فقط.

### نموذج مكتمل يُحتذى: البرمجة / أساسيات / L1

٩٠ سؤالاً نشطاً فريداً بلا تكرار، موضوعان فقط (التعليقات والمتغيرات)،
بالتوزيع المعتمد: ٣٠ اختياري + ١٠ لكل نوع من الستة الباقية.

> **عن الأسئلة المعطّلة:** الأسئلة الزائدة عن التوزيع لم تُحذف بل عُطّلت بـ`is_active = false`
> وتبقى في الداتابيس. الاستعلام يستثنيها، ويمكن إعادة تفعيل أي منها بتغيير الحقل.
> عند الاختيار تُعطى الأولوية للأسئلة **الأصعب** لأنها الأكثر قيمة.

### فحص التكرار — إلزامي قبل اعتماد أي مستوى

```sql
select level, count(*) filter (where is_active) as نشط,
       count(distinct question) filter (where is_active) as فريد
from public.questions
where track_id = '...' and section_id = '...'
group by level order by level;
```

لا بد أن يتساوى العمودان. عند وجود نسخ مكرّرة تُعطَّل النسخة الأحدث (`id` الأكبر) ويبقى الأصل.
وُجد ١٧ سؤالاً مكرّراً حرفياً في مستوى ٢ من البيانات الأصلية وعُولجت بهذه الطريقة.

### معايير جودة السؤال
- واقعي من ممارسة فعلية، مو حفظ نظري
- **الخيارات الخاطئة معقولة** — أخطاء يقع فيها المبتدئ فعلاً، لا حشو واضح
- ملتزم بموضوع مستواه، ما يخرج عنه
- غير مكرر مع أي سؤال موجود

### ⚠️ ألّا تكشف الإجابة الصحيحة نفسها

ثلاثة تلميحات تجعل اليوزر يخمّن بلا فهم، وكلها ممنوعة:

**١. الطول** — لا تكون الإجابة الصحيحة أطول من كل البدائل. الشرح مكانه حقل
`explanation` لا داخل الخيار. اجعلي أطوال الخيارات متقاربة.

**٢. المجال الدلالي** — البدائل يجب أن تكون في نفس مجال الإجابة الصحيحة وتبدو
معقولة. خيار مثل "لتقليل حجم الملف" أمام إجابة عن المنطق يُستبعد فوراً بلا تفكير.
اجعلي كل بديل خطأً شائعاً حقيقياً أو التباساً واردًا.

**٣. الموضع** — لا تتركّز الإجابة الصحيحة في موضع معيّن. كان التوزيع ٥١٪ في
الموضع الأول و٠.٦٪ في الأخير، أي أن اختيار الأول دائماً يعطي ٥١٪ بلا قراءة.

فحص الموضع:
```sql
select correct_answer, count(*),
       round(100.0*count(*)/sum(count(*)) over (),1) as نسبة
from public.questions
where type='multiple-choice' and is_active and jsonb_array_length(options)=4
group by correct_answer order by correct_answer;
```
المطلوب: كل موضع بين ٢٠٪ و٣٠٪ تقريباً.

لتوزيع المواضع بالتساوي على مستوى جديد، ضعي الإجابة الصحيحة في موضع يتناوب
`0,1,2,3` بدل الاعتماد على خلط عشوائي (العشوائي على عيّنة صغيرة يعطي ميلاً واضحاً):

```sql
with target as (
  select id, options, correct_answer,
         (row_number() over (order by md5(id::text || 'seed')) - 1) % 4 as want
  from public.questions
  where section_id = '...' and level = N
    and type in ('multiple-choice','code') and jsonb_array_length(options) = 4
),
parts as (
  select t.id, t.want, (t.options ->> t.correct_answer) as correct_txt,
         (select jsonb_agg(v order by ord)
            from jsonb_array_elements_text(t.options) with ordinality x(v, ord)
           where ord - 1 <> t.correct_answer) as others
  from target t
),
built as (
  select id, want,
    coalesce((select jsonb_agg(v) from (select value v from jsonb_array_elements(others) limit want) s), '[]'::jsonb)
    || jsonb_build_array(to_jsonb(correct_txt))
    || coalesce((select jsonb_agg(v) from (select value v from jsonb_array_elements(others) offset want) s2), '[]'::jsonb)
    as new_options
  from parts
)
update public.questions q set options = b.new_options, correct_answer = b.want
from built b where q.id = b.id;
```

فحص الطول:
```sql
with opt as (
  select q.id, length(t.value) as len, (t.ord-1)=q.correct_answer as ok
  from public.questions q,
       lateral jsonb_array_elements_text(q.options) with ordinality t(value, ord)
  where q.type='multiple-choice' and q.is_active
)
select round(100.0*count(*) filter (where lc > lo)/count(*),1) as نسبة_الصحيحة_الأطول
from (select id, max(len) filter (where ok) lc, max(len) filter (where not ok) lo
      from opt group by id) a;
```
المطلوب: قريبة من ٢٥٪، لا ٥٠٪.

> **تعديل معتمد على الخطة:** أُضيف موضوع **العمليات الحسابية** إلى L3.
> وصف القسم ينص على "المتغيرات وأنواع البيانات **والعمليات** والإدخال والإخراج"،
> ولم تكن العمليات الحسابية (الجمع والطرح والضرب وباقي القسمة وأولوية العمليات)
> مغطّاة في أي مستوى. هذه هي الخطة المعتمدة، ولا يُرجَع للتوزيع القديم.

## حالة التنفيذ

| المسار | القسم | الحالة |
|---|---|---|
| البرمجة | **S1 أساسيات** | ✅ **مكتمل — ٤٥٠ سؤالاً** · كل مستوى ٩٠ نشطاً فريداً بالتوزيع المعتمد |
| البرمجة | **S2 التفكير البرمجي** | ✅ **مكتمل — ٤٥٠ سؤالاً** |
| البرمجة | S3 البرمجة الكائنية | جارٍ — L1: **٩٠ ✅** · L2: **٩٠ ✅** · L3: **٩٠ ✅** · L4–L5: لم تبدأ |
| البرمجة | S4–S7 | لم يبدأ |
| بقية المسارات | الكل | لم يبدأ |

> "ما القيمة المطبوعة؟" أو "ما تعقيد هذه الخوارزمية؟" لأكثر من سؤال — تظهر
> كأنها مكرّرة في فحص التفرّد. اجعلي العنوان يصف الحالة تحديداً.
